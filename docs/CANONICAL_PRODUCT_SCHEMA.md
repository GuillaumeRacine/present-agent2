# Canonical Product Schema

This schema is the required output contract for all ingestion connectors (API or scraping).

If a source cannot produce the minimum required fields, do not ingest it into production inventory.

## 1) Required Fields (MVP)

```json
{
  "source": "etsy|ebay|shopify|manual|...",
  "source_product_id": "string",
  "canonical_url": "https://...",
  "title": "string",
  "description": "string",
  "brand": "string",
  "price": 49.99,
  "currency": "USD",
  "availability": "in_stock|out_of_stock|preorder|unknown",
  "images": ["https://..."],
  "categories_raw": ["string"],
  "tags_raw": ["string"],
  "ingested_at": "2026-02-23T12:34:56Z"
}
```

## 2) Recommended Fields (Strongly Preferred)

```json
{
  "rating_avg": 4.6,
  "rating_count": 132,
  "shipping_regions": ["US", "CA"],
  "shipping_speed_days_min": 2,
  "shipping_speed_days_max": 6,
  "material": "ceramic",
  "is_handmade": true,
  "is_personalizable": false,
  "seller_name": "string",
  "seller_id": "string",
  "license": "api_terms_v1",
  "attribution_required": false
}
```

## 3) Normalized Internal Fields (Post-Processing)

These are generated by your enrichment layer before Neo4j load:

- `interests_normalized[]`
- `occasions_normalized[]`
- `relationships_normalized[]`
- `gift_attributes` (boolean map used by explorer/presenter)
- `quality_signals` (review confidence, bestseller flags, metadata completeness)
- `duplication_fingerprint` (for dedupe)
- `composite_score` (ranking prior)

## 4) Validation Gates

A record is rejected if any condition is true:

1. Missing required fields.
2. `price <= 0` or `currency` missing.
3. No image URL.
4. No usable text (`title + description` under 24 chars total).
5. Duplicate of existing canonical fingerprint with lower quality score.
6. Source compliance/terms unclear (`license` missing for restricted sources).

## 5) Dedupe Strategy

Use layered dedupe:

1. Exact URL match (`canonical_url`).
2. Source ID match (`source + source_product_id`).
3. Fuzzy title + brand + near price (variant collapse).

Keep the richest record and merge compatible fields (`tags_raw`, `categories_raw`, reviews).

## 6) Versioning

- Current schema version: `v1`.
- Additive changes only in minor updates.
- Breaking changes require `v2` and migration script.
